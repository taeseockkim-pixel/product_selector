# 견적번호 누락 번호 선택

## 목표

견적을 삭제해 번호가 비어 있으면 새 견적 저장 시 누락 번호를 재사용할지, 현재 최댓값 다음 번호를 쓸지 사용자가 선택하게 한다. 화면의 미리보기 숫자만 바꾸지 않고 최종 배정은 Apps Script가 잠금 아래 대장을 다시 확인해 수행한다.

## 변경 내용

- [x] 견적 대장에서 NO와 견적번호를 함께 읽어 `가장 작은 누락 번호`와 `최대 번호 + 1`을 계산
- [x] 신규 견적 저장/메일 초안 제출 시 누락 번호 선택 모달 표시
- [x] 수정 리비전/기존 파일 덮어쓰기는 신규 일련번호 선택에서 제외
- [x] 선택 직전 다른 사용자가 해당 번호를 사용했으면 저장 접수를 거부하고 새로고침 안내
- [x] 대장에 기록되기 전 pending 견적 번호도 ScriptProperties 예약으로 막아 동시 저장 중 중복 방지
- [x] 일반 저장과 메일 초안 요청 모두 선택된 번호 방식 전달
- [x] `npm run test:quote-numbering`, `npm run test:quote-draft` 검증 통과
- [x] Apps Script 운영 URL을 **v121**로 갱신(기존 배포 ID/URL 유지)
- [x] 운영 URL 관리자 권한을 읽기 전용으로 확인
- [ ] 목록에서 실제 482 공백 사례의 두 선택지(482/489)를 브라우저에서 확인

## 번호 정책

- `누락 번호 재사용`: 현재 대장에서 가장 작은 빈 일련번호를 저장 직전 재계산한다.
- `마지막 번호 다음`: 현재 사용된 가장 큰 일련번호 + 1을 저장 직전 계산한다.
- UI가 본 선택 일련번호와 저장 잠금 시점의 실제 번호가 다르면 저장하지 않고, 목록을 새로고침해 다시 선택하라고 안내한다.
- 기존 견적/리비전/덮어쓰기는 변경하지 않는다.

# 스펙 입력 규칙 (SPEC_ENTRY_RULES.md)

스펙 데이터 품질 유지를 위한 규칙. `products.json` 편집 시 반드시 준수.

---

## 1. 언어 일관성

### 한글/영문 혼용 금지
같은 `seriesLabel` 그룹 내에서 동일 라벨의 값은 같은 언어를 사용해야 한다.

```json
// ❌ 잘못된 예 — 같은 시리즈에 한글/영문 혼용
{ "label": "단자 방식", "value": "Terminal Block Type" }
{ "label": "단자 방식", "value": "단자형" }

// ✅ 올바른 예
{ "label": "단자 방식", "value": "단자형" }
{ "label": "단자 방식", "value": "커넥터형" }
```

**원칙**: 기본적으로 **한글** 사용. 다음 예외 허용:
- 산업 표준 약어: RS-232C, TCP/IP, MODBUS, IP66, TFT LCD, SFC
- 사람 이름·제품명: Intel Core i5, Windows 11 Pro
- 고유 영문 모델 타입: Wide Range (카탈로그 원문이 영문인 경우)

### 특수 값
- **해당 없음**: `"-"` 사용 (한글 `없음`도 허용, 혼용 주의)
- **지원**: `"O"` 또는 `"지원"` 일관 사용 (시리즈 내 통일)
- **미지원**: `"X"` 또는 `"미지원"` 일관 사용

---

## 2. 숫자·단위 표기 형식

### 온도
```
-10°C ~ 65°C    ✅ (양쪽 모두 °C, ~ 양옆 공백)
-10~65°C        ❌ (왼쪽 °C 없음, 공백 없음)
-10℃ ~ 65℃     ❌ (℃ 기호 사용 금지, °C 사용)
```

### 길이/단위
```
1.5m    ✅ (소문자 m)
1.5M    ❌ (대문자 M은 메가를 의미)
```

### 점수/채널
PLC 아날로그/디지털 모듈:
```
"16점"  ✅ (한글 단위, I/O 점수)
"16ch"  ❌ (영문 ch 사용 금지)
"16채널" ❌ (시리즈 내 통일 필요 — 대부분 점 사용)
```

### TAG 수
SCADA 제품:
```
"150 TAG"   ✅
"무한 TAG"  ✅ (무한 TAG 전용 공식 표현)
"150TAG"    ❌ (공백 필수)
```

### 해상도
```
"1024 x 768"        ✅ (소문자 x, 공백 포함)
"1024×768"          ❌ (곱하기 기호 사용 금지)
"1024x768"          ❌ (공백 없음)
"1024 × 800 (WXGA)" ✅ (eXT2 시리즈 한정 예외)
```

## 3. 라벨 명명 규칙

같은 의미의 항목은 반드시 동일한 라벨명을 사용.

| 사용 라벨 | 사용 금지 |
|-----------|---------|
| `ch` | `채널수`, `AI`, `AO` |
| `점수` | `출력 점수`(CM3는 허용), `입력 수` |
| `동작 온도` | `작동온도`, `동작온도` |
| `보존 온도` | `저장온도`, `보관온도` |
| `상대 습도` | `습도`, `동작 습도` |
| `터치` | `터치스크린`, `터치 방식` |
| `방수/방진` | `방수`, `방진` |

---

## 4. 터치 방식 표기

| 터치 타입 | 올바른 표기 |
|-----------|-----------|
| 정전식 | `"정전식 (Capacitive)"` |
| 저항식 | `"Analog Resistive"` |
| 기타 | 카탈로그 원문 준수 |

---

## 5. source 필드 규칙

```json
"source": "catalog"    // 카탈로그 PDF 원문 기반
"source": "estimated"  // 추정값 (일관성 검사 제외, 영문 모드에서도 숨김 처리 가능)
```

- 카탈로그 미확인 추정치는 반드시 `"estimated"` 사용
- `"catalog"` 값은 실제 카탈로그 PDF 대조 후 입력
- 기존 `"catalog"` 값 수정 시 카탈로그 재확인 필수

---

## 6. 중복 라벨 금지

같은 제품 내 동일한 라벨은 하나만 존재해야 한다.

```json
// ❌ 잘못된 예
{ "label": "출력", "value": "TR Sink 0.5A" },
{ "label": "출력", "value": "16점" }

// ✅ 올바른 예 — 라벨을 다르게 구분
{ "label": "출력 형태", "value": "TR Sink" },
{ "label": "출력 전류", "value": "0.5A" }
```

## 7. 검증 명령어

수정 후 반드시 실행:

```bash
npm run check:spec-consistency   # 시리즈 내 스펙 일관성 검사
npm run check:i18n               # 영문 번역 누락 검사
npm run verify                   # 전체 데이터 유효성 검사
```

**기준**: `check:spec-consistency` ERROR 0건, `check:i18n` 0건 달성 후 커밋.

## 8. WARN 허용 목록

아래 항목은 카탈로그 검토 완료 후 의도적 차이로 확인되어 허용:

| 시리즈 | 라벨 | 이유 |
|--------|------|------|
| XP Series | 내장 이더넷 | F모델(전용) vs E모델(증설전용) 구분 |
| CP Series | 내장 이더넷 | CP4 이더넷 없음 vs CP3 있음 |
| 아날로그 입력 | 최대 분해능 | μV 실수값 vs 비트수 혼용 |
| Loadcell | 타입 | WG02E "Wide Range" 카탈로그 영문 공식명 |
| 시리얼 통신 | Port1/Port2 | 없음(미탑재) vs 실제 포트 타입 |
| SCADA Standard | 라이선스 | DS/RS(영문) vs VS/CS(한글) 제품군 차이 |
| SCADA Standard | TAG 수 | 무한 TAG(한글 공식명) vs N TAG |

## DDR-001 — 정적 JSON 데이터 소스

**결정**: 제품 데이터를 백엔드 API 없이 `products.json` 정적 파일로 관리.

**이유**:
- 제품 카탈로그는 분기 1~2회 업데이트 → 실시간 API 불필요
- 담당자가 JSON 파일 직접 편집 가능 → 별도 CMS 불필요
- Vercel 정적 배포로 운영 비용 0

**고려한 대안**:
- Headless CMS (Contentful, Sanity) → 과잉, 관리 복잡도 증가
- REST API + DB → 인프라 비용 발생, 현재 규모 대비 과잉

**트레이드오프**: 실시간 가격/재고 표시 필요 시 이 결정 재검토.

## DDR-002 — 선언적 필터 설정 레이어

**결정**: `filterConfig.ts` 에 `CategoryConfig > SubTypeConfig > FilterSection` 계층으로 필터 로직 선언.

**이유**:
- 새 카테고리/필터 추가 시 컴포넌트 수정 없이 config만 변경
- 필터 로직과 UI 완전 분리 → 테스트 용이
- AI 에이전트가 컴포넌트 대신 config만 수정하면 됨

**고려한 대안**:
- 컴포넌트 내 if/else 하드코딩 → 카테고리 추가마다 컴포넌트 수정
- 상태 기반 동적 필터 빌더 → 초기 구현 복잡도 과잉

## DDR-003 — products.json specs 배열에 상세 사양 저장

**결정**: 각 제품의 `specs: {label, value}[]` 배열에 카탈로그 전체 사양 저장.

**이유**:
- SpecModal 이 specs 배열을 그대로 테이블로 렌더링
- 제품별 사양 항목 수가 다름 → 유연한 배열 구조가 적합
- 카탈로그 PDF 없이도 앱에서 완결된 정보 제공

**구현 날짜**: 2026-04-27

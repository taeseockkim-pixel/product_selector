# 핵심 설계 신념 (Core Beliefs)

이 문서는 이 프로젝트의 모든 설계 결정의 기반이 되는 원칙들입니다.
새 기능을 추가하거나 리팩터링할 때 이 원칙에 반하지 않는지 확인하십시오.

---

## 1. 데이터는 코드 밖에

**"제품 정보는 `products.json` 에만 존재한다."**

- 컴포넌트 안에 제품명, 모델 번호, 사양 값을 하드코딩하지 않는다
- 카탈로그 업데이트 = JSON 파일 수정, 코드 배포 없이도 가능해야 한다
- `filterConfig.ts` / `plcTreeConfig.ts` 의 id 값은 products.json 의 subType 필드와 항상 일치해야 한다

---

## 2. UI는 멍청하게, 로직은 설정으로

**"컴포넌트는 렌더링만 한다. 필터/비교 로직은 config 레이어에 산다."**

- `ProductTable`, `LeftPanel` 등은 props를 받아 화면에 뿌리는 역할만
- 새 필터 조건 추가 = `filterConfig.ts` 의 `matcher` 함수 수정
- 컴포넌트가 `category` 를 직접 switch/if로 분기하면 냄새

---

## 3. 단순함이 확장성보다 먼저

**"지금 필요하지 않은 추상화는 도입하지 않는다."**

- 현재 상태 관리: `useState` 만으로 충분 → Redux/Zustand 도입 불필요
- 현재 라우팅: viewMode string으로 충분 → React Router 불필요
- 사용자가 10만 명이 되면 그때 재검토한다

---

## 4. 에이전트가 읽을 수 있는 문서

**"모든 설계 결정은 AI 에이전트가 맥락을 이해할 수 있도록 문서화된다."**

- "왜 이렇게 만들었는가"가 없으면 에이전트가 잘못된 방향으로 수정한다
- 설계를 바꿀 때는 코드보다 문서를 먼저 업데이트한다
- `AGENTS.md` 는 에이전트의 첫 번째 진입점이다

---

## 5. 사용자는 엔지니어가 아니다

**"CIMON 영업/기술 담당자가 고객에게 제품을 안내하는 도구다."**

- 필터 UI는 직관적이어야 한다 — 코드 용어 사용 금지
- 비교 기능은 "이 제품이 저 제품보다 나은 점"을 빠르게 보여줘야 한다
- 모달의 spec 테이블은 카탈로그 수준의 정보를 담아야 한다
